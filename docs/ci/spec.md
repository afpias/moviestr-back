# SPEC-008: Проверки pull requests и защита веток

| Поле                 | Значение                      |
| -------------------- | ----------------------------- |
| Статус               | реализовано в установочном PR |
| Последнее обновление | 2026-10-18                    |
| Зависимости          | GitHub Actions                |

## Цель и границы

Автоматически проверять PR, сохраняя ручное решение владельца о слиянии.
Входят обычный CI и защита main/dev. AI-ревьюер, GitHub App и обращения к платному API не входят.
По решению владельца от 2026-10-18 требования REV-003–010 к платному боту отменены; их ID не переиспользуются.

## Требования

- **REV-001.** PR в `dev` и `main` запускает `Validate` и `Build` без секретов.
- **REV-002.** Обе ветки запрещают прямой push, force push и удаление; проваленные проверки блокируют merge.
- **REV-011.** Слияние выполняет владелец вручную. Обязательное AI-одобрение не требуется.

## Состояния и ошибки

Каждый CI job переходит из queued в in_progress, затем success / failure / cancelled.
Ошибка установки зависимостей, линтера, типов, тестов, форматирования или сборки не считается успешной проверкой.

## Сценарии приёмки

- **AC-01:** ошибка теста делает Validate красным и блокирует merge в защищённую ветку.
- **AC-02:** ошибка сборки делает Build красным и блокирует merge.
- **AC-03:** зелёные проверки допускают ручное слияние без GitHub App, OpenAI key и AI review.

## Нефункциональные требования и трассировка

CI использует Node.js 24, Yarn Classic, frozen lockfile и read-only GitHub token.
REV-001: `.github/workflows/ci.yml`, локальные validate/build и проверки установочного PR.
REV-002,011: GitHub branch protection API; CI не выполняет merge и не получает write permissions.
