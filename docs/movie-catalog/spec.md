# SPEC-002: Каталог, сложность и кадры

| Поле                 | Значение                  |
| -------------------- | ------------------------- |
| Статус               | реализовано               |
| Последнее обновление | 2026-10-14                |
| Зависимости          | TMDB API, DEC-019–DEC-021 |

## Цель

Как игрок я хочу получать фильмы предсказуемой сложности и пять кадров от менее очевидного к более очевидному, чтобы
сложность раунда соответствовала выбранному режиму.

## Границы

### Входит

- весь доступный через TMDB Discover каталог;
- восемь вариантов жанра;
- пять процентилей известности;
- выбор фильма с пятью подходящими backdrops;
- эвристическая сортировка кадров и ограниченный OCR-фильтр;
- кэширование и дедупликация TMDB-запросов.

### Не входит

- IMDb, Кинопоиск или редакционный рейтинг;
- гарантированное распознавание главных актёров и смысла сцены;
- ручная модерация каждого кадра;
- управление токенами TMDB (серверное хранение описано в SPEC-007).

## Требования каталога

- **CAT-001.** Источником фильмов, названий, постеров и backdrops должен быть TMDB; runtime mock-каталог запрещён.
- **CAT-002.** Выборка не должна ограничиваться Top 250 или другим фиксированным локальным списком.
- **CAT-003.** Доступны жанры `all`, `action`, `comedy`, `drama`, `thriller`, `horror`, `science-fiction`, `animation`.
- **CAT-004.** Discover должен сортироваться по `vote_count.desc`, исключать adult- и video-записи.
- **CAT-005.** Фактический размер пула ограничивается доступными страницами TMDB, максимумом провайдера в 500 страниц и
  количеством результатов.
- **CAT-006.** Случайная позиция должна выбираться внутри процентиля текущей сложности, а не только на первой странице.
- **CAT-007.** Кандидаты выбранной страницы должны дополнительно ранжироваться по составной известности: 70% логарифма
  `vote_count` и 30% логарифма `popularity`.

## Процентили сложности

| Режим        | Диапазон позиции в отсортированном пуле |
| ------------ | --------------------------------------- |
| `easy`       | 0–10%                                   |
| `medium`     | 10–30%                                  |
| `hard`       | 30–55%                                  |
| `expert`     | 55–80%                                  |
| `impossible` | 80–100%                                 |

- **CAT-008.** Диапазоны не должны пересекаться и вместе должны покрывать весь доступный пул.
- **CAT-009.** Смена жанра должна вычислять процентиль внутри каталога этого жанра.

## Требования к кадрам

- **CAT-010.** Фильм должен иметь минимум пять горизонтальных backdrops шириной не менее 780 px.
- **CAT-011.** Изображения с языковой маркировкой TMDB должны исключаться до OCR как вероятные title cards.
- **CAT-012.** OCR должен сравнивать распознанный текст со всеми допустимыми названиями фильма.
- **CAT-013.** Кадр с распознанным названием фильма не должен попадать в раунд.
- **CAT-014.** Ошибка OCR или исчерпание бюджета не должны отклонять весь фильм; используются кадры без языковой
  маркировки TMDB.
- **CAT-015.** Из выбранных кандидатов формируются ровно пять кадров, распределённых по диапазону эвристической
  узнаваемости от меньшего `vote_count`/`vote_average` к большему.
- **CAT-016.** URL игрового кадра использует размер TMDB `w780`, не содержит название фильма и не раскрывает ответ.
- **CAT-017.** Оставшиеся четыре кадра должны предзагружаться в фоне после создания раунда.

Желаемая семантическая последовательность — атмосфера, сцена без главных актёров, характерная сцена, узнаваемый герой
или локация, очевидный кадр без названия. В текущей реализации это приближение, а не гарантированный контракт.

## Производительность и ошибки

- **CAT-018.** Первая и выбранная Discover-страницы кэшируются по жанру и номеру страницы.
- **CAT-019.** Детали, изображения и альтернативные названия кандидата загружаются одним запросом через
  `append_to_response=images,alternative_titles`.
- **CAT-020.** Одновременные одинаковые запросы должны использовать общий Promise; неуспешный запрос удаляется из кэша.
- **CAT-021.** Запрос TMDB должен завершаться контролируемой ошибкой после timeout, а неизвестный ответ проверяться до
  преобразования во внутреннюю модель.

Транспорт браузера — same-origin серверный прокси из [SPEC-007](../deployment/spec.md). TMDB-токен недоступен клиенту.

## Сценарии приёмки

### AC-01: Выбор из нижнего процентиля

- **Дано:** TMDB сообщает 10 000 доступных фильмов жанра «Фантастика».
- **Когда:** создаётся раунд `impossible` при минимальном случайном смещении.
- **Тогда:** выбирается позиция от 8 000 и запрашивается страница 401 с `with_genres=878`.

### AC-02: Один запрос данных фильма

- **Дано:** выбран кандидат с `backdrop_path`.
- **Когда:** адаптер собирает игровой фильм.
- **Тогда:** сведения, aliases и изображения получены одним movie details запросом с `append_to_response`.

### AC-03: Недоступный OCR

- **Дано:** кандидат имеет пять подходящих backdrops без языковой маркировки.
- **Когда:** OCR завершается ошибкой или timeout.
- **Тогда:** раунд всё равно создаётся из этих кадров без перебора фильма только из-за ошибки OCR.

## Известные ограничения

- TMDB не предоставляет семантическую сложность кадра и наличие главного героя.
- Полная OCR-проверка требует backend-конвейера; браузерный бюджет намеренно ограничен.
