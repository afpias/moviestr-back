# SPEC-001: Одиночная игра

| Поле                 | Значение                                                                  |

## Цель

Как посетитель без учётной записи я хочу сразу угадывать случайные фильмы по кадрам, чтобы проводить короткие игровые
сессии без предварительной настройки.

## Границы

### Входит

- одиночный раунд из пяти кадров;
- прямое переключение сложности и жанра;
- пропуск, неверный ответ, победа и поражение;
- переход на следующую сложность и повтор после поражения;
- автоматическое начало игры на главной странице.

### Не входит

- очки, таймер и таблица результатов;
- авторизация и профиль;
- одновременная игра нескольких пользователей;
- ручное создание отдельной игровой сессии.

## Требования

- **SOL-001.** При открытии `/` система должна автоматически начать раунд сложности `easy` и жанра `all`, если нет
  восстанавливаемого состояния.
- **SOL-002.** Раунд должен содержать ровно пять кадров одного фильма и показывать одновременно только текущий кадр.
- **SOL-003.** Пропуск на кадрах 1–4 должен открыть следующий кадр ровно на одну позицию.
- **SOL-004.** На пятом кадре действие без выбранного ответа должно называться «Сдаться» и завершать раунд поражением.
- **SOL-005.** Неверный выбранный ответ на кадрах 1–4 должен открыть следующий кадр, а на пятом — завершить раунд
  поражением.
- **SOL-006.** Верный ответ должен завершить раунд победой и показать правильное название фильма.
- **SOL-007.** После победы действие «Далее» должно открыть новый фильм следующей сложности в последовательности
  `easy -> medium -> hard -> expert -> impossible -> easy`.
- **SOL-008.** После поражения действие «Повторить» должно открыть новый фильм той же сложности и жанра.
- **SOL-009.** Пользователь может в любой момент заменить текущий раунд выбором другой сложности или жанра.
- **SOL-010.** «Перезапустить раунд» должен открыть новый фильм сложности `easy`, сохранив выбранный жанр.
- **SOL-011.** Во время загрузки нового фильма боковые панели и общий каркас страницы должны сохраняться.
- **SOL-012.** Одиночная игра не должна начислять или отображать очки.
- **SOL-013.** Повторная отправка действия во время состояния `submitting` должна быть заблокирована.
- **SOL-014.** Ошибка загрузки должна переводить игру в восстанавливаемое состояние с возможностью повторить запрос.

## Состояния и переходы

```text
idle -> loading -> playing
playing -> submitting -> playing
playing -> submitting -> won
playing -> submitting -> lost
won -> loading -> playing
lost -> loading -> playing
loading -> error -> loading
```

`currentFrame` существует только для активного раунда. После `won` или `lost` центральная область показывает
`roundResult`.

## Сценарии приёмки

### AC-01: Начало без стартового экрана

- **Дано:** пользователь впервые открыл `/`.
- **Когда:** приложение завершило начальную загрузку.
- **Тогда:** показан первый кадр раунда `easy`, а отдельной кнопки старта нет.

### AC-02: Последовательный пропуск

- **Дано:** открыт первый кадр и фильм не выбран.
- **Когда:** пользователь нажимает «Пропустить».
- **Тогда:** номер кадра становится `02/05`, а фильм раунда не меняется.

### AC-03: Победа

- **Дано:** идёт раунд `hard` и пользователь выбрал правильный фильм.
- **Когда:** пользователь нажимает «Угадать».
- **Тогда:** вместо кадра показан результат победы, а «Далее» запускает `expert`.

### AC-04: Поражение

- **Дано:** показан пятый кадр.
- **Когда:** пользователь сдаётся или отправляет неверный фильм.
- **Тогда:** показан правильный ответ, а «Повторить» запускает новый фильм той же сложности.

### AC-05: Прямое переключение

- **Дано:** активен незавершённый раунд `easy`.
- **Когда:** пользователь выбирает `impossible`.
- **Тогда:** загружается новый фильм `impossible`, не требуя ответа на предыдущий.

## Ошибки и пограничные случаи

- При отсутствии TMDB token показывается безопасное сообщение с указанием `VITE_TMDB_READ_TOKEN`.
- Потерянная локальная сессия очищается, после чего начинается новый `easy`-раунд сохранённого жанра.
- Действия без активного `gameId` ничего не отправляют.
- Ошибка ответа не должна ошибочно засчитываться как неверная попытка.

- Игровая сессия и проверка ответа выполняются в браузере и не защищены от просмотра пользователем.
- Мультиплеер требует отдельной утверждённой спецификации и server-authoritative backend.
